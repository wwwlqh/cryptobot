# ⚠️ EXACT-PINNED — the model artifacts are PICKLES, and a pickle is only
# loadable by the library version lineage that wrote it. These are NOT ordinary
# version floors; a silent minor bump breaks boot on any FRESH box.
#
# Learned the hard way 2026-07-25 during the Ireland->London migration: the
# fresh venv resolved `scikit-learn>=1.4` to 1.9.0 while every artifact in
# data/models was pickled by 1.8.0. HistGradientBoosting pickles reference
# sklearn's PRIVATE `_loss` module, which moved between those releases, so
# load_hgb() died with `ModuleNotFoundError: No module named '_loss'` and the
# scanner crash-looped 11 times and never booted. The already-running Ireland
# box was unaffected because its venv predated the release — i.e. the bug was
# invisible until someone built a box from scratch.
#
# Bump these ONLY together with a re-pickle of data/models (and re-run the
# checkpoint/parity tests), never as a routine upgrade. Same reasoning as the
# exact pin on predict_sdk in pyproject.toml.
scikit-learn==1.8.0
pandas==3.0.3
